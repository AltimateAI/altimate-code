# How agent memory frameworks bound prompt memory and decide what to forget

Date: 2026-10-01. Read-only research. Evidence tags: [V] verified against primary text (paper PDF or source code I read this session), [S] secondary source (blog, reverse-engineering post, search snippet), [U] unverified or from memory.

## 0. Headline findings (for the lessons loop)

1. Two production patterns dominate. (a) A small always-injected tier with a hard size cap (Letta blocks, Claude Code MEMORY.md at 200 lines or 25KB, ChatGPT saved facts and profile, Memobase `max_token_size`, Agno entity memory render bounds). (b) A retrieved tier selected by embedding top-k. Almost nobody makes the always-in-context tier dynamic per turn. That is what makes prefix caching work.
2. "Push" (framework injects) vs "pull" (model calls a tool) is the key axis for your requirement. Fully push: ChatGPT, Letta core blocks, Claude Code MEMORY.md, Memobase context(), Mem0 search-then-inject (app-controlled), Agno ALWAYS mode, ACE (whole playbook in prompt). Pull: Claude.ai conversation_search, Agno AGENTIC mode (`search_learnings`, `save_learning`), LangMem manage/search tools, Letta archival memory. Agno's own author says AGENTIC is preferred because ALWAYS captures everything indiscriminately [V, agno.com article] (a consolidation-quality warning for push-write).
3. Forgetting is mostly weak or absent. Mem0 has no TTL, decay or eviction [V: issue #5330 states this]. A-MEM has no forgetting [S]. The mechanisms that do exist and are principled: ExpeL votes (importance count, remove at 0) [V], ACE helpful/harmful counters plus a size-triggered prune [V], Graphiti bi-temporal invalidation (never deletes, sets `invalid_at`) [V], MemoryOS heat + FIFO/LFU [S/paper abstract-level], RIMRULE MDL consolidation [S].
4. LLM whole-document rewrite is dangerous. ACE measured context collapse: 18,282 tokens at accuracy 66.7 collapsed to 122 tokens at accuracy 57.1, worse than the 63.7 no-memory baseline [V]. Fix: itemized bullets with ids and delta (add/update/retire) operations, never monolithic rewrite.
5. Unchecked write paths rot. A 32-day Mem0 production audit found 97.8% of 10,134 entries were junk, including one hallucinated fact stored 808 times because recalled memories were re-extracted from context [V: issue #4573 content as fetched; single user report, not a benchmark].

## 2. Per-framework mechanics

### Letta / MemGPT
- MemGPT main context = system instructions + working context (editable, core) + FIFO queue of messages. At ~70% of window a "memory pressure" warning is inserted so the model can move facts to working context or archival; at 100% the queue is flushed to ~50% and a recursive summary of evicted messages is regenerated from the previous summary plus evicted messages. Retrieval from archival/recall is paginated to keep tool results bounded [V: arxiv.org/pdf/2310.08560].
- Modern Letta: memory blocks are "always visible - no retrieval needed", each has label/description/value/limit, can be `read_only`, and shared across agents [V: https://docs.letta.com/guides/agents/memory-blocks]. Descriptions matter because the agent uses them to decide what to write where.
- Sleep-time agents: a separate agent with tools that edit the primary agent's in-context (core) blocks, async and at configurable frequency [V: https://www.letta.com/blog/sleep-time-compute]. Letta Code "dreaming": subagents review recent conversations and consolidate lessons, step-based or context-window-based triggers [V: https://docs.letta.com/guides/agents/architectures/sleeptime and docs.letta.com/letta-agent/memory]. Backups are taken before restructure (split, merge duplicates) [V].
- Context Repositories/MemFS: `system/` dir always in system prompt; rest is progressive disclosure via file tree + frontmatter descriptions; reflection and defragmentation subagents work in git worktrees and merge by git [V: https://www.letta.com/blog/context-repositories/]. Conflict handling = git merge.
- Unverified: exact default block limit (secondary source says 8000 chars, hard ValueError past it); I could not read Letta source (404 on guessed paths).

### mem0
- Extraction prompt P = (summary S, last m messages, new pair). LLM extracts candidate facts. Update phase: for each fact, retrieve top-s similar memories, LLM picks ADD / UPDATE / DELETE (when contradicted) / NOOP via tool call [V: https://arxiv.org/pdf/2504.19413].
- Prompt rules: UPDATE if fact is richer ("likes cricket" -> "loves cricket with friends"), NOOP if semantically equal, DELETE on contradiction, keep ids stable [V: https://raw.githubusercontent.com/mem0ai/mem0/main/mem0/configs/prompts.py].
- Retrieval: embedding top-k, injected by the app. Graph variant Mem0g adds entity/relationship triples.
- Numbers (LOCOMO, paper) [V]: Mem0 J=66.88, p95 total latency 1.440s, 1,764 tokens; Mem0g J=68.44, 3,616 tokens; full-context J=72.90, 26,031 tokens, p95 17.117s; Zep J=65.99 with 3,911 retrieval tokens but a 600k-token memory graph; A-Mem J=48.38; LangMem J=58.10 with p95 search 59.82s; OpenAI memory J=52.90. Headline claims: 26% relative J gain over OpenAI, 91% lower p95 latency, >90% token cost saving vs full context. Note full context still scores higher on J (72.9 vs 66.9): bounded memory trades some accuracy. Memory store size: 7k tokens (Mem0), 14k (Mem0g) per conversation.
- No forgetting: issue #5330 states no TTL/decay/eviction [V]. Issue #4573 audit (single report): 97.8% junk of 10,134 entries; top junk categories: boot-file/system-prompt restating 52.7%, heartbeat noise 11.5%, architecture dumps 8.2%, transient state 7.4%, hallucinated profile 5.2%; 808 copies of one hallucination from recall re-extraction. Proposed fixes: tag recalled memories to prevent re-extraction, post-extraction quality gate, negative examples, REJECT action, identity-aware extraction [V as fetched, unaudited].

### Zep / Graphiti
- Bi-temporal: t_created / t_expired (transaction time) and t_valid / t_invalid (event time) per edge. New edges are compared by an LLM against semantically related existing edges; temporal contradictions set the old edge's `invalid_at` to the new edge's `valid_at` and stamp `expired_at`; "Graphiti consistently prioritizes new information" [V: https://arxiv.org/pdf/2501.13956].
- Source: dedupe prompt returns `duplicate_facts` (only from existing facts) and `contradicted_facts` (from existing or invalidation candidates), with explicit rule "NEVER mark facts with key differences (numbers, dates, qualifiers) as duplicates" [V: graphiti_core/prompts/dedupe_edges.py]. `resolve_edge_contradictions` only expires an older edge if intervals overlap and the old started earlier [V: utils/maintenance/edge_operations.py].
- Retrieval: cosine + BM25 + BFS, rerank. LongMemEval: Zep gpt-4o 71.2% vs full-context 60.2%, latency 2.58s vs 28.9s, context 1.6k vs 115k tokens; claims up to 18.5% accuracy gain, ~90% latency reduction [V paper table].
- Caveat from Mem0 paper: Zep memory not immediately available after write, async graph build; and 600k-token graph from per-node summaries [V, competitor claim].

### LangMem
- Memory types: semantic (collections searched at runtime, or profiles = single updated doc), episodic (successful interactions as examples), procedural (behavioral instructions refined via feedback) [V: https://langchain-ai.github.io/langmem/concepts/conceptual_guide/]. Core loop: accept conversation + current memory state, return updated memory state. Formation: hot path (tool call during chat, adds latency) vs background reflection.
- Prompt optimizer: `gradient` (critique + update, 4-10 calls), `metaprompt` (2-5 calls), `prompt_memory` (1 call); `min_reflection_steps` default 1, `max_reflection_steps` default 3 [V: reference page]. This is the closest analog to "lessons become part of a rewritten system prompt".
- Mem0 paper measured LangMem p95 search latency 59.8s, i.e. impractical for hot path [V, competitor claim].

### Agno Learning Machines
- Stores: user_profile, user_memory, session_context, entity_memory, learned_knowledge, decision_log. Modes: ALWAYS, AGENTIC, PROPOSE (agent proposes, human confirms; learned_knowledge only), HITL reserved [V: libs/agno/agno/learn/config.py].
- Learned knowledge: default mode AGENTIC, namespace "global"/"user"/custom (sharing boundary), vector store required, `recall(limit=5)`, `build_context()` returns the always-mode context string injected into the system prompt, `instructions()` carries mode-specific guidance separately [V source stores/learned_knowledge.py]. Prompt rules: "ALWAYS search before saving" to avoid dupes, skip search for routine operational tasks [V].
- Entity memory injected block: directory (one line per entity, newest first, up to 50) + up to 5 expanded entities, 10 live facts each, 5 events each, "with visible truncation markers"; fact supersession threshold 0.8 "conservative by design - a wrong supersession hides information" [V config.py].
- Curator: prune(max_age_days, max_count), deduplicate for exact/near-exact; "currently supports user_profile store only" [V curate.py]. So learned_knowledge has no automatic pruning in this version.
- Article (https://www.agno.com/articles/learning-machines) confirms ALWAYS vs AGENTIC and author prefers AGENTIC; does not discuss budgets or consolidation [V].

### cognee, A-MEM, MemoryOS, Memobase, Supermemory
- cognee memify: post-hoc graph enrichment (entity consolidation, cross-entity link proposal with confidence, coding-rules derivation, session persistence); inferred edges tagged with `feedback_weight: 0.2` so they are distinguishable and prunable; `dry_run=True` available [V docs]. Pruning of stale nodes not confirmed.
- A-MEM: note construction + top-k link generation + evolution of neighbor notes; token numbers 1,200-2,500 vs 16,900 [S]. In the Mem0 reproduction A-Mem scored J=48.38 [V].
- MemoryOS: 3 tiers; FIFO from short-term; heat-driven promotion; defaults short=10, mid=2000, long knowledge=100, retrieval queue 7, heat thr 5.0, sim thr 0.6 [S, fetched source summary]; reported +49.11% F1 / +46.18% BLEU-1 on LoCoMo (EMNLP 2025) [S].
- Memobase: buffer flush (~1024 tokens or ~1h idle), `context(max_token_size=..., prefer_topics=[...])` packs profile + latest events under a token cap [S/V README fetch]. Profile merge/forget rules not documented (unverified).
- Supermemory: vendor-reported LongMemEval-S Recall@20 97%; SMFS reduces cumulative tokens 3x (Claude) and 1.75x (Codex) [S, vendor]; graph relation semantics unverified.

### ChatGPT and Claude (public descriptions only)
- ChatGPT, per reverse engineering [S: https://manthanguptaa.in/posts/chatgpt_memory/, https://llmrefs.com/blog/reverse-engineering-chatgpt-memory]: no vector DB or RAG over history; four layers: session metadata, saved facts, ~15 recent conversation summaries (of user messages only), sliding window of the current session. Everything injected each turn in a fixed order. Trade-off named by authors: old context shapes new answers whether relevant or not.
- Claude.ai [S: https://manthanguptaa.in/posts/claude_memory/]: `<userMemories>` block of distilled stable facts + on-demand `conversation_search` (1-10 results, default 5) and `recent_chats`; depends on model deciding to search.
- Claude Code (official) [V: https://code.claude.com/docs/en/memory]: CLAUDE.md delivered as a user message after the system prompt (not in the system prompt), MEMORY.md index first 200 lines/25KB, topic files on demand, nested CLAUDE.md load when files in that dir are read, path-scoped rules, 4 memory types (user, feedback, project, reference), post-write size check that nags the model to shorten, frontmatter `modified` timestamp so staleness is visible, "if two instructions contradict each other, Claude may pick one arbitrarily" and `/doctor prompt-audit` for conflicts. Auto memory skips anything derivable from the codebase.
- OpenAI help page returned 403; official saved-memory capacity not verified.

### Procedural / skill memory
- Voyager: skill = verified code with LLM-written description; retrieval by embedding of the description against task + feedback; top-5 [U]. Skills only enter library after self-verification (environment feedback) [U]. Paper PDF too large to fetch.
- Agent Workflow Memory: induce workflows (not whole trajectories) at sub-task granularity; offline = all workflows into prompt; online = evaluator-gated (only successful episodes induce workflows), snowballing; +24.6% relative step success (Mind2Web cross-task) and +51.1% relative success on WebArena over baseline [V: https://arxiv.org/pdf/2409.07429 text].
- ExpeL: insights extracted by comparing fail/success pairs and lists of L successes; ops ADD / EDIT / UPVOTE / DOWNVOTE; importance count starts at 2, +1 on UPVOTE/EDIT, -1 on DOWNVOTE, removed at 0; rationale given: even successful trajectories can mislead [V: https://arxiv.org/pdf/2308.10144]. Experiences retrieved with Faiss kNN. Both insights and retrieval needed (ablation) [V]. No explicit size cap found [V negative]. Insights editable by humans [V].
- ACE: bullets = id + helpful/harmful counters + content; roles Generator/Reflector/Curator; deltas only; grow-and-refine with embedding dedup; refinement proactive (each delta) or lazy (only when window overflows) [V: https://arxiv.org/pdf/2510.04618 section 3.2]. Results: +10.6% agents, +8.6% finance; 86.9% lower adaptation latency; AppWorld 82.3% fewer rollouts [V]. Caching: 91.8% of input tokens served from cache with OpenAI API (GPT-5.1), billed-input cost -82.6% [V]. Robust to dedup threshold (50-90%) and prune trigger (10K-100K). Even injecting a harmful reflection every iteration cost only -4.0 points on FiNER (66.7 vs 70.7 baseline? see Table 17 in paper; exact framing not re-verified). Counters let the Curator "filter entries flagged potentially harmful" [V].
- Dynamic Cheatsheet: Game of 24 GPT-4o 10% -> 99% under DC-RS after storing a Python-solver snippet; DC-Cu rewrites the cheatsheet each step; DC-RS retrieves top-k similar past inputs/outputs and synthesizes [V: https://arxiv.org/pdf/2504.07952 text]. Memory is self-curated "concise, transferable snippets".
- Rule learning: HtT keeps counters of occurrence and correct answers per rule, filters by min occurrence k in {1,2,3} and min confidence p; hierarchical XML tagging helps retrieval from big libraries; library must fit in context (<= ~500 rules); +10-30% gains [S/V fetch of https://arxiv.org/html/2310.07064]. RIMRULE: MDL-guided greedy prune/generalize; consolidation shrank ToolHop 72->67 rules (acc 27.6->31.1) and BFCL 151->121 (54.8->56.6); 4-rule library from 90 examples gave +6.9 to +14 points [S: https://arxiv.org/html/2601.00086v3]. I could not locate a paper named "TRAN"; flagged unverified.

## 3. Prompt-caching implications

- Anthropic API cache order is tools -> system -> messages; a change at one level invalidates that level and everything after it; breakpoint should sit on the last stable block, not on content that changes per request; max 4 explicit breakpoints; cache read is 0.1x input (0.05x Opus 5.5, 0.025x Fable) and 5-min writes 1.25x; minimum cacheable size 512-4096 tokens by model; lookback 20 blocks [V: https://platform.claude.com/docs/en/build-with-claude/prompt-caching].
- Manus: KV-cache hit rate is "the single most important metric"; keep prefix stable, append-only context, no timestamps in the system prompt, deterministic serialization; mask tools rather than remove them [V: https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus].
- What frameworks do in practice:
  - ChatGPT/Claude: static system prompt first, memory block next, then conversation. Memory changes only when the profile regenerates (every day or few days [S]), so the profile is a cache-stable segment between regenerations.
  - Claude Code: memory goes in a user message after the system prompt, loaded at session start (stable within a session), so memory edits do not invalidate the system/tools prefix [V]. Detailed topic files arrive later as tool results (append-only).
  - Letta: blocks are compiled into the system prompt, so any block edit invalidates cache from the system level down. Letta's sleep-time agents rewrite blocks asynchronously, which batches changes between turns (an inference on my part, [U]).
  - ACE: long, append-mostly playbook; paper reports 91.8% cache reuse; delta updates and "do not rewrite" keep the prefix byte-stable between refinements [V].
  - Mem0/Zep/Agno-retrieval style: per-query retrieved memories change every turn; must be placed after the stable prefix (or in the latest user turn), otherwise they bust the cache. No framework doc I read states this explicitly [U as a stated framework recommendation].
- Design implication: split memory into (1) a frozen "digest" tier rendered deterministically (stable sort, no timestamps) and refreshed only at session start or at explicit consolidation, and (2) a per-turn retrieved tier appended after the cache breakpoint. Retrieval keys should be derived from non-model signals so it does not depend on the model calling a tool.

## 5. Patterns worth copying for the lessons loop

1. Two tiers, deterministic. Tier A "digest" = top-N lessons by score, rendered stable-sorted and byte-identical across turns, inside a hard budget (pick tokens, not entries; Claude Code uses 200 lines/25KB, ACE tolerated 10K-100K, HtT <= ~500 rules). Tier B = retrieved per turn by non-LLM signals (path/glob match like Claude Code `paths:` rules, tool/command being run, embedding similarity), placed after the cache breakpoint with a small k (Agno 5, Voyager 5 [U]).
2. Path- or trigger-scoped lessons beat embedding retrieval for a CLI agent. Claude Code's `paths:` glob scoping and RIMRULE's symbolic state filter are push mechanisms that need no model tool call. For data engineering use triggers like dbt model path, warehouse type, command name, file extension.
3. Itemized lessons with ids and counters, delta operations only. ACE bullet (id, helpful, harmful) and ExpeL ops (ADD/EDIT/UPVOTE/DOWNVOTE, start at 2, delete at 0) are small, auditable, and avoid the context-collapse failure. Never let an LLM rewrite the whole lessons file.
4. Update counters from non-LLM outcomes (command succeeded/failed after a lesson was in context, user corrected, test passed). Mem0's audit shows LLM-only feedback signals are almost never sent. Outcome-based votes also give a principled eviction score.
5. Eviction score for the digest tier: utility = helpful - harmful (ExpeL/ACE), times recency decay, times scope breadth; with a pin flag for human-authored lessons. Optional heat model (MemoryOS: visits, interaction length, recency) or simple access_count * 0.5^(days/7) (proposal in Mem0 #5330 [S]). Demote to Tier B (retrieval-only) before deleting; keep an archived record (Graphiti-style `invalid_at` rather than hard delete).
6. Supersession, not overwrite. Graphiti: new fact invalidates old with timestamps, never deletes; dedup prompt rule "never call facts duplicates if numbers, dates or qualifiers differ" is directly applicable to conventions ("use 4-space indent" vs "use 2-space"). Agno: only supersede when judge confidence >= 0.8 because a wrong supersession hides information.
7. Write-gate to stop junk. Add a REJECT/quality gate (Mem0 audit recommendations): do not extract from recalled memory (tag injected lessons and strip them from the extraction input), reject transient state, system-prompt restatements, anything derivable from the repo (Claude Code auto memory already skips derivable facts), and require evidence/provenance (session id, diff, user correction).
8. Dedup + merge in a background pass, not on the hot path. Letta sleep-time/"dreaming", LangMem background reflection, ACE lazy refine (only when budget exceeded), cognee memify. Triggering consolidation on budget overflow (ACE lazy, Claude Code write-time nag) keeps the digest byte-stable between consolidations, so cache invalidates only when you consolidate. Use embedding dedup threshold roughly 0.5-0.9 (ACE insensitive across range; tune with your own data).
9. Human-in-the-loop promotion. Agno PROPOSE mode, Letta read-only blocks, Claude Code CLAUDE.md vs auto memory split: lessons enter as candidates; only counters or a human move them into the always-in-context tier. Team-shared conventions benefit from namespace/sharing boundary (Agno namespace "global"/"user"/custom).
10. Make staleness visible. Claude Code stamps `modified`; Agno renders as-of dates for facts; Graphiti has valid/invalid times. Show the date or lesson age in the rendered lesson only if it does not break cache stability (use coarse buckets, or put dates in Tier B).
11. Add a prompt-audit pass for conflicts (Claude Code `/doctor prompt-audit` finds contradictory/stale instructions) and a hard size warning on write.
12. Cache hygiene: render Tier A deterministically (sorted by id, no timestamps, fixed template), keep it before conversation, change it only at session start or consolidation, keep per-turn memory after the last breakpoint, and measure `cache_read_input_tokens` as a regression metric.
